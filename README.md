# Nexus AI

Nexus AI is a multi-tenant AI Knowledge Workspace where teams can sign up, create workspaces, upload documents, and chat with their data using a powerful RAG pipeline and AI tool calling.

## Architecture

![Architecture Flow](https://via.placeholder.com/800x400.png?text=Nexus+AI+Architecture)

The platform is built using a modern Next.js App Router stack.

### Request Flow
1. **User** -> Authenticates via **Supabase Auth**
2. **Workspace** -> User selects or creates a Workspace.
3. **Upload Document** -> File is pushed to **Supabase Storage**.
4. **Processing** -> Next.js API extracts text using `pdf-parse`/`mammoth`, chunks it via **LangChain**.
5. **Embeddings** -> Chunks are vectorized using **Gemini Embedding Model**.
6. **Vector DB** -> Vectors are stored in PostgreSQL using **pgvector**.
7. **Chat/RAG** -> User asks question -> **Gemini Embeddings** -> Similarity Search (filtered by Workspace ID) -> Top 5 chunks -> **Gemini 2.5 Flash**.
8. **Tool Calling** -> LLM uses tools like `save_task` or `summarize_workspace` directly within the chat.

## Database Schema Documentation

Our application leverages PostgreSQL with Prisma ORM.

### Models
- **User**: Handled via Supabase Auth, mirrored in public schema. (`id`, `email`, `createdAt`)
- **Workspace**: Multitenant container. (`id`, `name`, `slug`, `ownerId`)
- **Membership**: Junction table for User/Workspace. (`workspaceId`, `userId`, `role`)
- **Document**: Represents uploaded files. (`workspaceId`, `filename`, `storageUrl`, `status`)
- **DocumentChunk**: The RAG text chunks. Uses raw `pgvector` for the `embedding` field.
- **Conversation & Message**: Chat history tracking.
- **Task**: To-do items generated by the AI agent.
- **ToolExecution**: Audit logs for AI actions.

## RAG Explanation

The Retrieval-Augmented Generation (RAG) pipeline is designed for high accuracy and tenant isolation:
1. **Vectorization**: Documents are chunked (1000 characters, 200 overlap) and embedded using Google's `text-embedding-004`.
2. **Metadata Filtering**: *Workspace Isolation* is strictly enforced at the database level. The raw SQL query for retrieval includes `WHERE "workspaceId" = currentWorkspaceId`, guaranteeing zero cross-workspace data leakage.
3. **Generation**: The retrieved context is passed as a system prompt to Gemini 2.5 Flash to synthesize a response.

## AI Safety

Nexus AI implements multiple layers of AI safety:
- **Prompt Injection Defense**: System prompts are isolated from user inputs. The AI is explicitly instructed to refuse out-of-scope requests.
- **Tenant Isolation**: Row-Level Security equivalent is handled via explicit `workspaceId` filtering in all Prisma queries and raw SQL.
- **Tool Validation**: Arguments passed to tools are strictly validated using `zod` schemas.
- **Secure Fallbacks**: If information is missing, the AI is instructed to safely reply: *"I couldn't find that information in your workspace."*
- **No Secret Exposure**: Internal environment variables and database URLs are strictly kept on the server environment.

## Setup Guide

### 1. Prerequisites
- Node.js 18+
- Supabase Project (PostgreSQL + pgvector)
- Google Gemini API Key

### 2. Environment Variables
Copy `.env.example` to `.env` (or use the one provided) and fill in:
```env
DATABASE_URL="postgresql://[user]:[password]@[host]:6543/postgres?pgbouncer=true"
DIRECT_URL="postgresql://[user]:[password]@[host]:5432/postgres"
NEXT_PUBLIC_SUPABASE_URL="your-supabase-url"
NEXT_PUBLIC_SUPABASE_ANON_KEY="your-anon-key"
SUPABASE_SERVICE_ROLE_KEY="your-service-key"
GOOGLE_GENERATIVE_AI_API_KEY="your-gemini-key"
```

### 3. Database Setup
```bash
# Push schema to the database (creates tables)
npx prisma db push

# Generate Prisma Client
npx prisma generate
```

> **Note on pgvector**: Ensure the `vector` extension is enabled in your Supabase project (done automatically by the Prisma schema `postgresqlExtensions`).

### 4. Storage Setup
Go to your Supabase Dashboard and create a new public Storage Bucket named `documents`.

### 5. Run the Application
```bash
npm run dev
```

## How to Test This Assessment

To verify that the application meets all core requirements:

1. **Sign Up / Login:** Create a throwaway account at `/signup` or use an existing one.
2. **Workspace Isolation Test:**
   - Go to your default workspace and upload a document containing a unique fact (e.g., "The secret code is 84729").
   - Click your Workspace name in the sidebar and create/switch to a **second workspace**.
   - In the second workspace, go to the Chat and ask: "What is the secret code?".
   - The AI must respond with "I couldn't find that information in your workspace" — proving strict isolation in the shared vector store.
3. **Tool Calling Test:**
   - In the chat, type: "Create a task to review the Q3 earnings report".
   - The AI will execute the `save_task` tool. 
   - Navigate to the **Tasks** page to see the new task.
   - Navigate to the **Tool Logs** page to see the full audit trail and schema payload of the tool execution.
4. **Honest "I don't know" Test:**
   - Ask a question completely unrelated to any uploaded document. The AI will refuse to hallucinate.

## Deployment Guide

### Vercel Deployment
1. Push the code to GitHub.
2. Import the project in Vercel.
3. Ensure the Build Command is `npm run build` and Install Command is `npm install`.
4. Add all environment variables listed in the Setup Guide to Vercel.
5. Deploy.

*Note on Serverless function limits: Document processing might take time for large PDFs. For heavy production use, consider offloading `api/documents/process` to a background worker like Inngest, Upstash, or Trigger.dev.*
